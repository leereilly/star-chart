# Contributing to Star Chart

Thanks for your interest in improving Star Chart! This guide covers the local
workflow and the invariants CI enforces.

## Prerequisites

- **Node 24** (the action runtime). CI runs on Node 24. Newer local versions
  generally work for development; the committed bundle targets Node 24.
- npm (the repository ships a `package-lock.json`; use `npm ci`).

## Getting started

```bash
npm ci
npm test
```

## Project layout

```
src/
  index.ts          Action entrypoint (thin; wires @actions/core -> run)
  run.ts            Dependency-injected orchestration
  lib.ts            Side-effect-free programmatic API
  models/           Shared domain types
  config/           Input parsing, validation, themes
  api/              Octokit client, retries, repository + history fetch
  history/          normalize -> window -> bucket -> chart model
  renderers/        shared, contributions, charts (line/area/bar/sparkline),
                    animation, freeze (frame-freezing for raster),
                    frames + gif (raster GIF pipeline), registry (index.ts)
  utils/            dates, numbers, svg escaping, path, atomic write
tests/              vitest suites, fixtures, helpers
scripts/            build, generate-examples, test-bundle, browser-preview
examples/           committed, deterministic example SVGs
docs/               static Primer setup site and frozen-data previews
assets/fonts/       Roboto TTF bundled into dist/ for GIF text rendering
dist/               committed, bundled action + programmatic API
lee.gif             committed reference animated-GIF sample (regenerated by `npm run examples`)
```

## The pipeline

Data flows in one direction:

**API client → `normalizeHistory` → `selectWindow` → `bucketWindow` →
`buildChartModel` → renderer → SVG string → atomic write.**

Each step is independently testable and pure where possible. `run()` takes an
injected `RunDeps` object so the entire orchestration can be exercised without
touching the real network or `@actions/core`.

## Adding a renderer

1. Add a `render<Style>(model: ChartModel): string` function.
2. Register it in `src/renderers/index.ts`.
3. Add the style to the `ChartStyle` union and the `style` enum in
   `src/config/inputs.ts` and `action.yml`.
4. Add tests and example coverage.

Renderers must emit **standalone** SVG: no DOM, scripts, or external resources.
Local gradients, hatch patterns, and bounded blur filters are supported;
their deterministic IDs must resolve within the document.
Escape all text/attributes via `src/utils/svg.ts`, use
CSS classes (not `var()` in presentation attributes) for themed colours, and
keep geometry finite.

## Regenerating `dist/` and `examples/`

These and `docs/samples/` are committed and **verified for drift in CI**. If you change source or
rendering, regenerate and commit them:

```bash
npm run build
npm run examples
git add dist examples docs/samples lee.gif
```

CI fails if a fresh `npm run build` / `npm run examples` would produce any
tracked change or new untracked file. Builds are reproducible — no build-time
timestamps are injected, and examples use the checked-in snapshot's fixed clock.

To also rebuild the Rails social videos, install FFmpeg locally and run:

```bash
npm run build
npm run examples:videos
```

This regenerates the same SVG/GIF examples plus
`assets/rails-rails-social-loop.mp4`, its identical `-candidate.mp4` copy,
and the source/encoded-frame PNGs in `assets/validation/`. The 1080×588,
30fps, 11.6-second cut builds in light mode, fades to dark, reverses, then
fades back to the opening frame. It uses the authentic frozen Rails API
fixture, not synthetic growth or live requests. Tile geometry is resolved at 1800px
before rasterizing to 1080px; FFmpeg does not stretch the square cells.
Video regeneration is opt-in so ordinary examples and CI need no FFmpeg.

### Refreshing the authentic showcase snapshot

`scripts/fixtures/github-star-history.json` contains a frozen, authenticated
GitHub REST API snapshot captured **2026-09-14T03:45:49.440Z**. The showcase's
`rails/rails` metadata records creation at **2008-04-11T02:19:47Z** and **58,751**
current stars. All **33 pages / 963 weeks** of the native
[`/repos/rails/rails/stargazers/history`](https://api.github.com/repos/rails/rails/stargazers/history)
endpoint sum to **58,750** recorded additions. Metadata and history differ by
one star; both values are preserved. These are native recorded weekly counts,
not a reconstructed star/unstar ledger or an estimate made by scaling a curve.
Requests are sequential, so the snapshot is not an atomic view of GitHub.

The same capture includes authentic `rails/propshaft` (**1,044 stars**, 9 pages)
and `rails/sprockets-rails` (**593 stars**, 27 pages) for aggregates and comparisons.
The fixture stores source URLs, API version, collection times, pagination counts,
metadata, weekly totals and daily count bins only: no tokens or stargazer accounts.
The API's original weekly boundaries and daily bins are retained, including the
first week overlapping creation. Rendering clips the displayed lifetime to the
exact repository creation instant and snapshot time, and buckets it into 52
columns (12 for grouped comparisons), not hundreds of cramped columns.

Refreshing is a **manual, opt-in network operation** requiring an authenticated
`gh` CLI with access to the native history endpoint:

```bash
npm run examples:refresh
npm run build
npm run examples:videos
```

The refresh follows every `Link: next` page, checks the API rate budget and
validates records before replacing the fixture. Errors fail explicitly and leave
the old fixture intact; there is no synthetic fallback. Review the resulting
provenance, update the dated assertions in `tests/example-data.test.ts` and the
snapshot details here and in the README, then regenerate assets. Ordinary
builds, examples, videos and tests remain offline and deterministic. SVGs embed
provenance; videos also record the source, date and exact counts in MP4 metadata.
Only zero-star and one-star edge cases use explicitly labeled synthetic data.

## Tests & snapshots

- Every rendered SVG is parsed as XML and checked for duplicate IDs, broken
  `url(#…)` references, scripts/external resources, and non-finite geometry.
- Snapshots and examples use a fixed clock for determinism.
- Animation tests assert timing/step invariants (grid-aligned tips, chronological
  overlap, loop hold/reset), not just string presence.
- The bundle smoke test runs the built action in a subprocess against a preload
  `fetch` stub; unexpected network requests fail the test.

## Commit conventions

Keep changes focused. Regenerate `dist/`/`examples/` in the same PR as the
source change that requires them. Do not add publishing, tagging, or release
automation without discussion.
